# Firmware 13.00 — wallpaper assets, measured

Everything here was read off a test console on firmware 13.00, not taken from prior art. The prior-art
screen table in the design spec is written against older firmware and **is wrong for 13.00**.

## How this was measured

`/system_ex/vsh_asset/bg_hub_default.dds.zst` was read, decompressed and its DDS header parsed. Every
other `*.dds.zst` in the same directory was then read and parsed the same way. Reproduce with:

```bash
python ZstdWrap/inventory.py backups        # after the stock assets were copied off the console
```

Frame sizes vary by more than 4× while the decoded content is identical in size — the images simply
differ in how well BC7 compresses them. Content size is what matters for a replacement.

## What this establishes

- **The texture loader honours the format declared in the header.** The console ships two different
  formats in one directory (BC7 with a DX10 header, and BC1 with a legacy header), so a replacement is
  free to choose a cheaper format rather than being locked to BC7. That matters a great deal: BC1 is
  half a byte per pixel and trivial to encode, so a theme need not ship PC-encoded BC7.
- **Header flavour must be preserved per asset.** A legacy 128-byte header and a DX10 148-byte header
  differ by 20 bytes with an identical pixel payload. `mkdds.py replace` therefore compares *pixel*
  lengths and keeps the reference's header, which is why the BC1 asset could be replaced without
  changing its declared format.
- **Dimensions are uniform.** All 16 are 3840×2160, so one generated image size serves every screen.

## Screen mapping

**The naming scheme is `bg_<title id>.dds.zst`** — the number is a Sony **system title ID**, not an
arbitrary identifier. Confirmed by the PS5 dev wiki, which names them:
`NPXS40037 TITLEID_SIE_RNPS_PSPLUS`, `NPXS40047 TITLEID_SIE_RNPS_GAME_STORE`,
`NPXS40071 TITLEID_SIE_RNPS_LIBRARY`, `NPXS40063 TITLEID_SIE_RNPS_EXPLORE`,
`NPXS40080 TITLEID_SIE_RNPS_SHAREPLAY`, `NPXS40053 TITLEID_SIE_MONTE_CARLO_ICON_VIDEO_HOME`,
`NPXS40054 TITLEID_SIE_MONTE_CARLO_ICON_MUSIC_HOME`. So any system screen that gains a title ID can in
principle gain a background, and a name can be resolved from the ID rather than guessed.

### The two prior-art sources disagree, which is a finding in itself

| Asset | `ps5-wallpaper-modd` | `ps5-wallpaper-changer` |
|---|---|---|
| `bg_NPXS40075` | Gallery | Notifications |
| `bg_NPXS40080` | Share Play | Friends |
| `bg_NPXS40110` | Disc Player | Trophies |
| `bg_NPXS40139` | Library | Game Base (chat/groups) |
| `bg_NPXS40144` | Unsupported Disc | Accessibility |
| `bg_NPXS40154` | Remote Play | On-screen keyboard |

For every screen the user observed, **`ps5-wallpaper-modd` agrees and
`ps5-wallpaper-changer` does not**. The most likely explanation is that the mapping changed between
firmware versions — which is exactly why it has to be measured per firmware rather than copied, and why
the screens were labelled on the console. The three "disputed" rows above are the ones worth checking by
hand.

### How to finish this

Each asset currently carries a distinctly labelled texture: `hub_default`, `Library_BG`, `load_error`,
and `N40037`…`N40154`. Visit a screen, note the label, and fill in the table. Undo everything with the
app's Restore defaults (the originals are also held on-console at `/data/prospero-themes/backup/original/`).

The labels were applied as of commit `bd895d2`; the console currently holds them.
